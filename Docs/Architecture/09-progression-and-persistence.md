# Task 09 runtime contract

This extends the Task 08 tick and the Task 05–07 stateless planner. RunSession still owns every run value. GameManager owns a plain HighScoreStore; there is no additional singleton or independent presentation model.

The tick evaluates `d = clamp01(max(elapsedPlayingSeconds / DifficultyDuration, doubleAbsoluteDistance / DifficultyDistance))` before preflight/input/contact prediction. Cruise target is Lerp(22,50,d); nominal allowed-slot occupancy is Lerp(.25,.8,d). Movement then uses that target, contacts/rewards commit, logical travel/time commit once, distance-plus-coins score and best recompute, fuel drains, feedback finishes, and one terminal decision runs. Continuing ticks maintain content/rebase/publish; terminal ticks use GameManager's guarded final transaction. Paused/GameOver actual speed is zero; target/difficulty remain frozen until the next Playing tick. Reset restores difficulty0/target22/occupancy.25.

## Deterministic density context

**A row's absolute world address finalizes its density.** `SpawnDirector.RowOccupancy(block,row)` evaluates the same curve using the immutable context `(elapsed=0, distance=block*480 + row*60)`. This deliberately chooses the distance input for world content. Session occupancy is the current run's time/distance challenge; a future row's occupancy is the challenge at that row's world coordinate. They are distinct projections, with no promise that the visible window has precisely the current snapshot's probability. At normal 300m lookahead, content can preview the distance curve by .05 normalized difficulty. Time-only advancement changes the cruise/nominal snapshot immediately on the next Playing tick; it never redraws existing rows.

This rule is independent of asynchronous generation, caller batching, traversal, steering, ticks, origin and pool availability. `PlanAt(long)` reconstructs the same value forever for a given seed/config/address. No history/epoch dictionary or mutable configuration is required. The current window stays four BlockPlans; existing fixed arrays/64 diagnostics remain bounded. Validation can reconstruct neighboring/future reservations without committing them or influencing RNG.

For each eligible lane, reuse the existing counter address `(seed,block,GameplayStream,1+row*3+lane+1)` and threshold its uniform value by that row's occupancy. Exclude the protected lane, first180m and the120m tail. Every slot keeps its type sample and stable spawn sequence. Type selection remains moving8m/s or stationary0; full envelope rejection may fall back to stationary as before. Maximum player50/minimum22 versus traffic8 remain the conservative validation bounds at every difficulty. Fuel offsets120/300/450, protected lanes, transition buffers and pickup-envelope validation are unchanged. All actual fuel is reserved before travel; misses cannot change the plan or remove a required opportunity silently.

`EligibleSlots`, `ProposedTraffic`, `AcceptedTraffic`, `RejectedTraffic`, `TrafficPoolMisses`, `MovingFallbacks` and existing SpawnedStationary/SpawnedMoving separate probability, safety filtering, fallback, realized rentals and saturation. AcceptedTraffic includes accepted proposals whose pools missed; realized traffic is the sum of the two spawned counters. Counters reset with the run. Pure planner statistics have no pool stage and label pool misses N/A.

## Score and persistence transactions

Score remains `floor(double distance) + CoinScore*coins`, using long multiplication and an int.MaxValue comparison before narrowing. Coin count saturates too. AddCoin and the post-movement recomputation call the same GameManager.CaptureBest flow: cache max(previous session best,current score,loaded store best) and retain it on Session. They perform no preference write/Save. Snapshot observers are read-only consumers.

HighScoreStore.Load reads once per store, treating missing/negative as0. SetIfHigher changes only the cached candidate/dirty flag. Flush writes/Save only when dirty and clears dirty only after completion; it also protects a higher value already stored under the same key. Production key is `NTR.HighScore.v1`; constructor injection supports isolated keys. The internal three-method preferences seam tests reads/writes/Save counts without touching production preferences.

GameManager flushes after the final GameOver state/snapshot commit and before RunEnded, before menu cleanup, before restart/start can discard an outgoing session, at explicit Menu Quit, application pause(true), application quit and owner teardown. Ordinary in-game Pause only caches; it does not flush. Duplicate boundaries with no new candidate do nothing. Reload-disabled rebootstrap captures the previous candidate before detaching an old session; owner shutdown flushes before discarding composition. No presenter saves; no event subscription is added for persistence.

Tests replace the editor-only store factory with a fresh in-memory adapter per manager, including additive saved-scene tests. The saved-scene smoke replaces the store before starting gameplay and deletes only its unique key. The temporary standalone probe injects its unique store before Awake and uses existing session/score/end APIs. No test deletes all preferences, changes application identity or mutates the production key.
